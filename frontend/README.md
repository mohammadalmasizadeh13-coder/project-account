# رابط حسابداری زرنگار

رابط فارسی و راست‌به‌چپ سامانه با React و Vite ساخته شده است. صفحهٔ `/` سامانه را معرفی می‌کند؛ `/register` حساب خصوصی تازه می‌سازد؛ `/login` برای ورود و `/account` برای استفاده از حسابداری است. کاربر پس از ثبت‌نام وارد حساب خودش می‌شود.

## اجرا

از پوشهٔ `frontend`:

```powershell
npm ci
npm run dev -- --host localhost
```

سرور بک‌اند باید روی `http://127.0.0.1:8000` اجرا شود. Vite درخواست‌های `/api` را به آن منتقل می‌کند. اطلاعات مالی در سرور ذخیره می‌شوند؛ اجرای رابط به‌تنهایی برای ثبت‌نام یا حسابداری کافی نیست. برای اجرای هر دو سرویس با یک دستور، [راهنمای فارسی](../docs/NOOR_GOLD_GUIDE.fa.md) را ببینید.

## محیط حسابداری

بخش‌ها مطابق مجوزهای مالک یا همکار نمایش داده می‌شوند:

- خانه: خلاصهٔ فروش، سود، موجودی، نرخ‌ها، اسناد اخیر و یادآوری‌ها.
- ثبت‌ها: خرید و فروش، هزینه، موجودی اولیه، مشتریان، تسویه، چک و نرخ‌های دستی.
- گزارش‌ها: فروش، سود، هزینه، موجودی، گردش اسناد، مشتریان، چک‌ها و تراز طلا.
- مشتریان: مشخصات، سابقهٔ معامله و تسویه، تولد و پیگیری.
- همکاران تجاری: دفتر جداگانهٔ طلا و تومان، خرید جنس با اجرت طلایی، پرداخت و حواله.
- تنظیمات حساب: کاربران و مجوزهایشان، تغییر رمز، پشتیبان و بازیابی.

هر حساب تازه دفتر مستقلی دارد. مالک می‌تواند همکار بسازد و مجوز خواندن یا نوشتن بخش‌های حسابش را تعیین کند. ایجاد همکار حساب حسابداری تازه‌ای ایجاد نمی‌کند. کنترل دسترسی در سرور نیز اعمال می‌شود.

«خرید طلای متفرقه» برای طلای دست‌دوم یا کم‌عیار، وزن و عیار واقعی را همراه معادل `وزن × عیار ÷ ۷۵۰` نگه می‌دارد. تعداد جنس در معادل و مبلغ کل لحاظ می‌شود و مبلغ خرید بر پایهٔ نرخ طلای ۷۵۰ زمان ثبت محاسبه می‌شود. هزینهٔ جانبی ثبت‌شده نیز به مبلغ اضافه می‌شود.

در «همکاران تجاری»، ماندهٔ طلا و تومان جداگانه و با گردش بدهکار و بستانکار ثبت می‌شود. ماندهٔ مثبت نشان می‌دهد ما به همکار بدهکاریم. اجرت درصدی خرید جنس به طلای بدهی اضافه می‌شود؛ پرداخت طلا، وجه نقد یا حواله در دفتر همان همکار ثبت می‌شود. این اشخاص طرف حساب تجاری هستند؛ دسترسی ورود به سامانه از بخش کاربران تعیین می‌شود.

مبالغ حسابداری برحسب تومان هستند؛ مقدار اصلی هزینه‌های طلا و ارز همراه معادل تومان زمان ثبت حفظ می‌شود. تغییر نرخ جاری، مبلغ اسناد و هزینه‌های ثبت‌شده را بازنویسی نمی‌کند. تاریخ‌ها با تقویم فارسی و زمان‌های ثبت با منطقهٔ زمانی `Asia/Tehran` نمایش داده می‌شوند. یادآوری چک، تولد و پیگیری داخل سامانه نمایش داده می‌شود.

## بررسی و ساخت

```powershell
node --test src/*.test.js
npm run build
node accounting-browser-check.mjs
```

آزمون مرورگر به Chrome نصب‌شده در مسیر پیش‌فرض ویندوز و محیط مجازی بک‌اند نیاز دارد. با پایگاه داده و نمایهٔ موقت، ثبت‌نام، ورود، جداسازی حساب‌ها، نگهداری پیش‌نویس و خرید طلای متفرقه را بررسی می‌کند. تصاویر در `artifacts/` همین پوشه نوشته می‌شوند.

خروجی ساخت در `dist/` قرار می‌گیرد. در استقرار، مسیرهای برنامه باید به `index.html` برگردند و `/api` به بک‌اند منتقل شود؛ تنظیم Nginx پروژه همین کار را انجام می‌دهد. دستور `docker compose up --build -d` از ریشهٔ پروژه هر دو سرویس را روی `http://localhost:3000` اجرا می‌کند.
